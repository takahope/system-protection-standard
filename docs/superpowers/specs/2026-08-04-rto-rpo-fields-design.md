# 新增 RTO 與 RPO 欄位設計規格 (Design Spec)

## 1. 目的 (Objective)
在系統清冊的新增與編輯表單中，擴充營運持續計畫 (BCP) 相關的災難復原指標。除了現有的「最大可容忍中斷時間 (MTO)」外，新增「復原目標時間 (RTO)」與「資料回復點目標 (RPO)」兩個欄位，並加上直白的名詞解釋以幫助填表人理解。

## 2. 功能需求與介面設計 (Requirements & UI Design)
*   **欄位位置**：在「系統詳情」與「表單新增/編輯」畫面中，這兩個欄位將歸屬於「韌性與對外服務」群組，並緊接排列在「最大可容忍中斷時間」之後。
*   **欄位屬性**：均為文字輸入框 (Text Input)，如同現有的最大可容忍中斷時間。
*   **名詞解釋 (Tooltip)**：沿用系統現有的 `SYSTEM_FIELD_HELP_TEXT` 機制，在表單標題旁顯示 `!` 提示圖示，懸停時顯示說明。
    *   **最大可容忍中斷時間**：此系統最多可以壞掉多久
    *   **復原目標時間(RTO)**：系統恢復到最低可運作標準的時間
    *   **資料回復點目標(RPO)**：備份週期，就是你可以忍受遺失多久以前的資料

## 3. 系統實作細節 (Implementation Details)

### 3.1 前端修改 (`AppScript_Index.html`)
1.  **修改 `SYSTEM_FIELD_SCHEMA`**：
    在 `SYSTEM_FIELD_SCHEMA` 陣列中，找到 `key: '最大可容忍中斷時間'` 的位置，在其後新增兩個物件：
    ```javascript
    {key:'復原目標時間(RTO)', group:'韌性與對外服務', countMissing:true, formKey:'rto'},
    {key:'資料回復點目標(RPO)', group:'韌性與對外服務', countMissing:true, formKey:'rpo'},
    ```
2.  **修改 `SYSTEM_FIELD_HELP_TEXT`**：
    新增/更新這三個欄位的說明文字：
    ```javascript
    '最大可容忍中斷時間': '此系統最多可以壞掉多久',
    '復原目標時間(RTO)': '系統恢復到最低可運作標準的時間',
    '資料回復點目標(RPO)': '備份週期，就是你可以忍受遺失多久以前的資料',
    ```

### 3.2 後端與資料庫 (Spreadsheet) 相依性
*   前端表單欄位是動態依賴 `SYSTEM_FIELD_SCHEMA` 生成的，新增欄位後，存檔與讀取機制會自動嘗試對應 Google Spreadsheet 的欄位。
*   **【必要前置作業】**：部署此修改前或部署時，必須在試算表的「系統清冊」工作表中，新增對應的標題欄位 `復原目標時間(RTO)` 與 `資料回復點目標(RPO)`，否則後端儲存時可能會略過這兩個欄位或發生對應不到的狀況。

## 4. 驗收標準 (Acceptance Criteria)
1. 在新增/編輯系統表單的「韌性與對外服務」群組中，可以看見「復原目標時間(RTO)」與「資料回復點目標(RPO)」。
2. 上述三個 BCP 欄位標題旁有 `!` 提示，游標移入能正確顯示設定的白話文解釋。
3. 表單填寫後送出，並能在試算表正確寫入這兩個新欄位的值。
4. 點擊系統卡片展開詳情時，詳情清單中會顯示這兩個新欄位的設定值。
