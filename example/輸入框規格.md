# 職務配置新增彈窗：人員輸入框規格

## 1. 適用範圍

本文件描述「職務配置管理」頁面中，點擊「新增職務配置」後彈出的 Modal 表單內，人員搜尋輸入框的實際規格。

適用欄位包含：

- **人員 Email / 姓名**：必填欄位，前端 DOM id 為 `assignmentPersonInput`。
- **直屬主管 Email**：選填欄位，前端 DOM id 為 `assignmentManagerInput`。

兩個欄位共用同一份人員候選清單。

## 2. 元件型態

此輸入框使用瀏覽器原生 HTML `datalist` 自動完成機制，不是自製下拉選單元件。

目前前端結構如下：

```html
<datalist id="assignmentPersonnelList">
  <option value="姓名 (email)"></option>
</datalist>

<input
  type="text"
  class="form-control"
  id="assignmentPersonInput"
  list="assignmentPersonnelList"
  placeholder="選擇姓名 (email)"
>
```

主管欄位同樣透過 `list="assignmentPersonnelList"` 綁定同一份候選清單。

## 3. 候選資料來源

候選清單由職務配置管理頁初始化時取得：

- 前端呼叫：`API.getAssignmentFormOptions()`
- 後端函式：`getAssignmentFormOptions()`
- 人員資料來源：`DataService.getSheet1Data()`
- 來源表：人員主檔

後端會將每筆人員轉成以下格式：

```javascript
{
  email: p.email,
  name: p.name,
  label: `${p.name} (${p.email})`
}
```

前端渲染 `<datalist>` 時，使用 `label` 作為 `<option>` 的 `value`。

顯示格式固定為：

```text
姓名 (email)
```

範例：

```text
王小明 (ming@example.com)
```

候選資料會依 `label.localeCompare(..., 'zh-Hant')` 排序。

## 4. 搜尋與顯示行為

此欄位支援以下操作：

- 使用者可以直接輸入文字。
- 使用者可以輸入姓名、Email 或其他關鍵字，由瀏覽器原生 `datalist` 篩選建議項目。
- 使用者點擊或聚焦輸入框時，瀏覽器可顯示候選清單。
- 在未輸入任何文字時，瀏覽器通常會顯示全部候選名單；實際展開方式依各瀏覽器對 `datalist` 的原生實作而定。

重要限制：

- 使用者雖然可以自由輸入文字，但送出時不能是任意文字。
- 送出前必須能對應到人員主檔中的既有人員。

## 5. 驗證規則

### 5.1 人員 Email / 姓名

此欄位必填。

驗證時會先執行：

```javascript
String(value || '').trim()
```

若欄位為空，顯示錯誤：

```text
請選擇人員
```

若欄位非空，會呼叫 `_findPersonnelOption(value)` 比對候選清單。比對方式如下：

- 將輸入值 `trim()` 並轉小寫。
- 比對每筆候選的 `label.toLowerCase()`。
- 比對每筆候選的 `email.toLowerCase()`。

因此有效輸入只接受以下兩種形式：

- 完整候選文字：`姓名 (email)`
- Email 本身：`email`

如果輸入值無法命中候選清單，顯示錯誤：

```text
指定的人員不存在於人員主檔
```

注意：目前程式碼不接受「只輸入姓名」作為有效送出值。使用者可以輸入姓名關鍵字搜尋候選，但送出值仍需是完整 `姓名 (email)` 或 Email。

### 5.2 直屬主管 Email

此欄位選填。

若欄位空白：

- 不顯示錯誤。
- 送出時 `managerEmail` 會是空字串。

若欄位非空：

- 驗證方式與人員欄位相同。
- 必須命中完整 `姓名 (email)` 或 Email。
- 若無法命中候選清單，顯示錯誤：

```text
指定的人員不存在於人員主檔
```

## 6. 送出資料格式

送出前端表單時，不會直接送出輸入框中的顯示文字，而是送出解析後的人員 Email。

成功通過驗證後，payload 格式如下：

```javascript
{
  email: person.email,
  orgCode: org.code,
  title,
  managerEmail: manager ? manager.email : ''
}
```

其中：

- `email` 來自人員欄位命中的候選資料。
- `managerEmail` 來自主管欄位命中的候選資料；若主管欄位空白則為空字串。

後端 `addAssignment(assignObj)` 會再次檢查：

- `email` 是否存在於人員主檔。
- `orgCode` 是否存在於組織主檔。
- `title` 是否有填寫。

## 7. 錯誤呈現

欄位錯誤由 `_setAssignmentFieldError(inputId, errorId, message)` 控制。

當有錯誤訊息時：

- 對輸入框切換 class：`form-control--error`
- 將錯誤文字寫入對應的 `.form-error`

人員欄位錯誤容器：

```html
<div class="form-error" id="assignmentPersonError"></div>
```

主管欄位錯誤容器：

```html
<div class="form-error" id="assignmentManagerError"></div>
```

## 8. 視覺樣式

輸入框使用共用 `.form-control` 樣式：

- 寬度：`100%`
- padding：`.5rem .75rem`
- 字級：`.9rem`
- 邊框：`1px solid var(--color-border)`
- 圓角：`var(--radius-sm)`
- 背景色：`var(--color-surface)`

聚焦時：

- 移除瀏覽器預設 outline。
- 邊框改為 `var(--color-primary)`。
- 顯示 `0 0 0 3px rgba(26,115,232,.2)` 陰影。

錯誤時：

- 套用 `.form-control--error`
- 邊框色改為 `var(--color-danger)`

此外，針對有 `list` 屬性的 `.form-control`，目前 CSS 會隱藏 Chrome / WebKit 的原生 datalist 箭頭：

```css
.form-control[list]::-webkit-calendar-picker-indicator {
  display: none !important;
}
```

## 9. 目前行為摘要

| 行為 | 規格 |
| --- | --- |
| 可直接輸入文字 | 可以 |
| 可輸入關鍵字搜尋建議 | 可以，透過瀏覽器原生 `datalist` |
| 點擊輸入框顯示候選 | 可顯示，依瀏覽器原生行為 |
| 未輸入時顯示全部候選 | 通常會顯示，依瀏覽器原生行為 |
| 可只輸入姓名並送出 | 目前不支援 |
| 可輸入完整 `姓名 (email)` 並送出 | 支援 |
| 可輸入 Email 並送出 | 支援 |
| 可輸入不存在的人員並送出 | 不支援，會顯示錯誤 |
| 人員欄位可空白 | 不可 |
| 主管欄位可空白 | 可以 |
